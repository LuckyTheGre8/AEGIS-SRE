# v0.4 — Runtime-generated diagnostics

Load the synthetic incident and click Investigate. Gemini proposes a READ_ONLY generation action. Aegis creates one disposable CreateOS sandbox, starts a real HTTP backend on loopback port 3000 and a proxy on 8080 configured to forward to unused port 3001, and confirms proxy HTTP 502 plus backend HTTP 200. These are actual HTTP responses in the guest.

`LLMProvider.generateDiagnosticTool` receives the incident, hypotheses, fixture contract, and observed evidence. Gemini writes source at runtime; the application contains no final diagnostic template. Trusted fixture/bootstrap/runner programs are infrastructure, separate from the generated source. The existing GeneratedTool schema records id, name, purpose, language, source, entrypoint, timeoutSeconds, risk, and expectedOutput.

Pipeline: strict Zod validation → 16000 UTF-8 byte limit → Acorn syntax parsing → syntax-tree dangerous-operation allowlist → deterministic tool policy → exact-source upload → guest runner execution → actual stdout/stderr/exitCode/durationMs → GENERATED_TOOL evidence with source SHA-256 and sandbox provenance. Host-side parsing never evaluates generated source.

The golden path supports a deliberately narrow JavaScript program: immutable declarations, data expressions, readConfig(), three fixed loopback probe targets, and JSON output. Generated code has no imports, arbitrary calls, functions, loops, assignments, computed properties, filesystem access, shell access, or general network client. The supplied guest functions perform bounded config reads and HTTP GETs. The runner also limits API calls, output size, CPU execution and wall time. Node vm is an additional capability restriction, **not a security boundary**; the disposable CreateOS VM is the actual isolation boundary. There are no credentials in that VM and public ingress is disabled by the existing provider.

Hard limits: MAX_GENERATED_TOOLS=3 total model tool responses, MAX_TOOL_RETRIES=2, MAX_COMMAND_SECONDS=20, one sandbox and three planning turns. Every generation attempt counts, including invalid output. Rejected source is never uploaded. Safe validation feedback can drive regeneration; runtime failures retain their actual evidence. Finally cleanup runs on every path, and destruction must be confirmed.

The existing Generated source tab shows the returned source, purpose, risk, validation checks, policy decision and hash. Output shows sandbox ID/status and observed command results. Hypothesis updates cite actual evidence IDs. Fixture diagnosis remains distinct from production diagnosis: final outcome is INCONCLUSIVE and production action NOT_EXECUTED. No patch or final fix verification is implemented.
