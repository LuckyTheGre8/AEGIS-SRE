# v0.3 — Bounded investigation

Configure server-only `GEMINI_API_KEY`, optional `GEMINI_MODEL` (default `gemini-3.5-flash-lite`), and the existing CreateOS variables. Restart, load the demo incident, and click Investigate. Gemini alone implements LLMProvider. No additional provider SDK or multi-provider selection was added.

The loop permits three model turns, two distinct fixed diagnostics, and one sandbox. Strict Zod validation rejects unknown fields, invented evidence IDs, and confirmed production-root-cause claims. Policy records ALLOW, DENY, or REQUIRE_APPROVAL; only allowed fixed read-only commands execute. Cleanup uses the existing confirmed-destruction path. Confidence is a model estimate, not a calibrated probability.

`POST /api/investigate` accepts only the bounded incident/fixture schema and returns after cleanup. `GET` returns `{running,lastResult}` from process memory. Reproduction fixtures, generated diagnostic tools, patches, validation, and production actions are outside v0.3.

## Official API discrepancy

The [Google structured-output guide](https://ai.google.dev/gemini-api/docs/generate-content/structured-output) showed `responseFormat.text.mimeType` as `application/json`. The live API rejected that spelling with HTTP 400; the [generateContent API reference](https://ai.google.dev/api/generate-content) defines the enum as `APPLICATION_JSON`. The implementation follows the live API/reference, supplies a Zod-generated JSON schema, and sends the key through `x-goog-api-key`. API error bodies and model thoughts are not exposed.
