# v0.5 — Fresh-sandbox patch verification

The existing demo investigation now continues from generated-diagnostic evidence to a model-generated patch. Gemini's `generatePatch` receives actual HTTP/config evidence and returns a single guarded replacement for `/upstreamPort` in `/workspace/fixture-config.json`, plus a concise root cause, rationale, and evidence IDs. It chooses the replacement value; the orchestration code never substitutes a hardcoded corrected port. Unknown fields, executable content, other files/paths, invalid ports, invented evidence IDs, stale old values, and no-op changes are rejected.

The human-readable diff is rendered deterministically from the observed original config and the model's replacement. It is a display of that exact data patch, not an independently generated or trusted shell program. The before/after config content and original model proposal are retained in the result.

The server creates a NEW CreateOS sandbox with a different ID, recreates the original broken fixture, and runs `node /workspace/health-check.cjs`. Actual pre-patch responses must show proxy HTTP 502 and healthy backend HTTP 200. The fresh config must match the observed diagnosis precondition. A trusted guest script applies only the validated JSON replacement, signals the fixture process to reload, and waits for an acknowledgement containing the exact new config. No model-generated shell commands execute.

The same health-check program runs again after reload. The proxy must return HTTP 200. The minimal regression check requires a healthy backend with its expected JSON payload, an unchanged backend response relative to the pre-patch observation, and the proxy forwarding that same payload. All command stdout/stderr/exitCode/durationMs values are retained and become evidence.

VERIFIED requires a distinct validation VM, real pre-patch 502, successful exact patch application/reload, real post-patch 200, regression PASS, and confirmed validation destruction. Diagnosis destruction is also required for the final successful result. Any failure produces FAILED_VALIDATION/FAILED, retaining partial observations and cleanup status. Unresolved cleanup in either sandbox blocks another app run. Browser disconnect does not cancel cleanup.

The existing Fix & validation panel shows model root cause, generated diff, BEFORE/AFTER statuses, REGRESSION, FIX STATUS, both sandbox IDs, command receipts, and cleanup. Verification is explicitly for the synthetic fixture. Production action remains NOT_EXECUTED and requires human approval; this app has no production mutation path.

Limits remain three planning turns, three generated tools, two tool retries, and twenty seconds per command. v0.5 permits at most one diagnosis and one fresh validation sandbox, and one generated patch per investigation. Existing baseline/smoke paths remain available.
